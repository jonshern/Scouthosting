# The Compass app on an iPhone

The Compass app (`mobile/`, Expo / React Native) is the parent and leader app: home, calendar and event pages with RSVPs and permission slips, chat, photos and your profile. Troop admin (roster, treasury, billing, the website) stays on the website. This page installs it on your own iPhone from the Mac. The App Store is a separate step ([app-store.md](app-store.md)).

It's the same setup as Waypoint (`jonshern/bluecard` docs/ios.md) and Lantern. If Xcode is already set up for one of those, skip to step 5.

## Once

1. Install **Xcode** from the Mac App Store, open it once, and let it install the iOS platform.
2. `brew install cocoapods`
3. In Xcode: **Settings > Accounts > +**, **Apple ID**, sign in, select the Personal Team, **Manage Certificates > + > Apple Development**.
4. Optional: build in the Mac's Tailscale address so sign-in works out of the box: `echo "EXPO_PUBLIC_COMPASS_BASE_URL=https://<mac>.<tailnet>.ts.net" > mobile/.env.local` (`mobile/scripts/phone.sh` prints the address). Without it, set it on the phone on the sign-in screen (**Server**) or in **Profile > Server**.
5. `mobile/scripts/ios.sh check` says what to fix, if anything.
6. Plug the iPhone in, unlock it, tap **Trust**, and turn on **Settings > Privacy & Security > Developer Mode** (the phone restarts).
7. `mobile/scripts/ios.sh`. The first build takes 10 to 20 minutes.
8. First open: **Settings > General > VPN & Device Management**, tap your Apple ID, **Trust**. Then sign in.

With a free Apple ID the copy stops opening after 7 days: run the script again (your sign-in and the saved copy stay). A free Apple ID also allows only 3 self-built apps per phone.

## Push notifications

A free Apple ID can't sign an app that receives push notifications, so the script leaves them out (`COMPASS_IOS_NO_PUSH=1`, see `mobile/app.config.js`) and the app simply never registers for them. With the paid Apple Developer team: `APPLE_TEAM_ID=<team> COMPASS_IOS_PUSH=1 mobile/scripts/ios.sh`. That copy lasts a year. EAS and store builds are untouched; they always include push.

TestFlight (no cable, updates by themselves, for other leaders and parents too): `APPLE_TEAM_ID=<team> mobile/scripts/testflight.sh` builds on the Mac and uploads to App Store Connect ([testflight.md](testflight.md)).

## With no signal

Every page the app loads is saved on the phone (`mobile/src/api/offline.ts`). When the server can't be reached (airplane mode, Tailscale off, the Mac asleep), the app shows the last copy of home, the calendar, event pages, chat channels and messages, photos and the scout list, with a note at the top saying how old it is. RSVPs, posts, uploads and anything else that changes something still need the server and say so. The saved copy is wiped on sign-out. Errors the server actually sends (a sign-in that's been revoked, a page you can't see) are never covered up by the saved copy.

## How it's put together

- `mobile/app.json` holds the settings; `mobile/app.config.js` lets the script swap the team (`APPLE_TEAM_ID`), bundle id (`COMPASS_IOS_BUNDLE_ID`) and leave out push.
- iOS 27 closes any app without the scene life cycle. `mobile/plugins/with-ios-scene.js` (same as Waypoint's and Lantern's) switches the generated app over; `mobile/tests/ios-scene.test.ts` checks it.
- `mobile/ios/` is generated by `npx expo prebuild` and isn't checked in. When the checkout's path has a space (`/Volumes/Crucial X9/...`), the script builds from a copy in `~/Library/Caches/compass-ios` (or `COMPASS_IOS_BUILD_DIR`).
- `mobile/scripts/ios.sh dev` installs a development copy that loads live code from the Mac.

## Troubleshooting

No certificate: step 3. "Developer Mode disabled": step 6. "Untrusted Developer": step 8. Stuck on the splash: you installed a `dev` copy without the Mac's dev server; run the script without `dev`. "Maximum number of apps for free development profiles": the phone already has 3; delete one or use the paid team. A signing error naming `aps-environment`: you ran with `COMPASS_IOS_PUSH=1` on a free Apple ID.
